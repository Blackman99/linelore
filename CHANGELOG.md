# Changelog

## Unreleased
- **Editors** (`editors/`). One key on the line you're reading, in four editors. **Neovim** (0.9+): `:Linelore` or a keymap opens a float at the cursor with focus in it; `⏎`/`gx` opens the link under the cursor, `o` the PR, `y` copies, `q` closes; the lookup runs in the background and the float warns when the buffer has unsaved changes. **Emacs** (27.1+): `M-x linelore` (region for a range) fills `*linelore*` with buttons; `TAB` walks links, `o` opens the PR, `w` copies, `g` looks again, `C-u` asks for a summary once; text wraps under its label at the window width. **VS Code**: three tasks (this line, a range of lines…, open the PR) and `Ctrl+Alt+L` / `Ctrl+Alt+Shift+L` bindings. **Helix** (25.07+): `space l l` for the line or selection, `space l o` for the PR. Neovim and Emacs parse `--json` and show summaries in their own labelled section; VS Code and Helix show the plain output. Dates are UTC, as in the CLI.
- **Editor tests in CI.** A new `editors` job installs Neovim, Emacs and Helix: the Neovim and Emacs plugins render ten JSON cases headless, Helix must load the config, and the VS Code tasks and bindings are checked; the JSON fields the plugins read are pinned by tests. Missing editors are skipped locally and fail in CI.
- **`--summarize`, opt-in and labelled.** Hands the facts to a model command *you* configured (`--summarize-cmd 'llm -m gpt-4o-mini'` or `LINELORE_SUMMARIZE_CMD`; anything that reads a prompt on stdin) and prints its answer after them under `Summary (generated by llm, may be wrong; not checked by linelore)`. linelore bundles no model, key or network call; the variable alone never runs anything. In `--json` the answer is a separate `model_summary` field (`by`, `text`, `error`, `disclaimer`) and every fact field is unchanged. The label shows only the program name, never its arguments. Output is stripped of terminal escapes (cursor-back word re-wraps, as `ollama run` streams them, are replayed rather than dropped) and capped at 4,000 characters. Tried end to end with a local Qwen2.5 1.5B through ollama. A missing, failing, silent or slow command (`LINELORE_SUMMARIZE_TIMEOUT`, default 120 s; the whole process group is stopped) gets a one-line reason on stderr and exit code 4, with the facts printed as usual. `LINELORE_SUMMARIZE_PROMPT` replaces the instruction.

## 0.3.0 – 2026-10-19
- **GitLab.** gitlab.com and self-managed GitLab: commit → merge requests → the issues each MR closes (`closes_issues`) → diff notes from the MR discussions, replies included. Shown as `MR !4112`; subgroups (`group/sub/project`) work. Token: `GITLAB_TOKEN`. gitlab.com only shows discussions to signed-in users, so without a token review comments are skipped with a note instead of failing.
- **Gitea and Forgejo** (Codeberg, gitea.com, code.forgejo.org, self-hosted): commit → PR → `Fixes`/`Closes`/`Resolves` references looked up as real issues (title and state) → review comments. Token: `GITEA_TOKEN` or `FORGEJO_TOKEN`. Gitea only links a PR to its merge commit, so when a line came in through a merge commit linelore finds that merge locally and asks again (never blaming a later merge for a direct push).
- **Forge detection.** Read from the remote URL (known hosts, `gitlab.*` / `gitea.*` / `forgejo.*` / `github.*` names, `~/.ssh/config` aliases like `github-work`). Override with `--forge {github,gitlab,gitea,forgejo}`; `--api` for self-hosted, where `/api/v4` implies GitLab and `/api/v1` Gitea. Unknown hosts get a note saying which flag to pass instead of a request to the wrong API.
- **`--open`** opens the PR/MR in your browser after printing the lore: the most recently merged one for a range, the commit page when there is no PR (or with `--offline`). On a machine with no desktop it prints the URL on stderr instead of starting a console browser, so `--json --open` keeps stdout clean.
- **JSON** gains a top-level `forge` field (`"github"`, `"gitlab"`, `"gitea"` or `null`). Everything else keeps its shape on every forge.
- **Clearer errors.** Rate limits, 401s, missing repos and unpushed commits name the host and the token variable to set; an API URL that returns HTML says so; slow forges get a 30 s timeout (`LINELORE_TIMEOUT`). A commit that isn't on the forge yet is a note, not a failure. The exit-3 failure note no longer also claims "offline".
- **Nicer terminal output.** Open PRs read "still open" and closed-unmerged ones "closed without merging" (no more "merged ?"); URLs are dimmed; long PR bodies and review comments wrap to the terminal width (single lines when piped); excerpts drop template headings, markdown link targets and `Signed-off-by` trailers; in a range, a PR shared by several commits is told once ("same PR as above").
- **Fixes.** GitHub Enterprise GraphQL now goes to `/api/graphql` (was `/api/v3/graphql`); for GHES hosts the token comes from `gh auth token --hostname HOST`; promoted issue links use the right host instead of always github.com. Cache keys include the forge. `Fixes https://…/issues/N` URLs and nested `group/sub/project#N` refs are recognised.
- **Cached "no PR" answers expire** (#3, #7). Empty answers on disk (no PR for this commit, no review comments, an issue that 404s) are trusted for an hour and then asked again, so a PR opened after your first look is found; real answers stay cached for good. When a "no PR" note comes from the cache it says how old it is, also when the same answer is used again later in the run. `LINELORE_CACHE_EMPTY_TTL` changes the hour (`0`: don't keep empty answers; anything that isn't a number ≥ 0, `nan` and `inf` included, means the default). Gitea/Forgejo no longer caches whether a repo or commit exists, so "not pushed yet?" clears as soon as you push.
- **Gitea/Forgejo: every page of a PR's reviews** (#4, #9, #15). Reviews are read page by page (`X-Total-Count` / `Link`; linelore builds the page URLs itself, so the token never follows a `Link` elsewhere) up to 500 reviews, and inline comments come from the newest 50 reviews that have them (by review id, whatever order the server lists them in). `Link` is read per RFC 8288 (`rel="next"`, bare `rel=next`, lists like `rel="prev next"`); when it and `X-Total-Count` disagree, linelore asks for the next page, and an empty page ends it. Past either limit a note says what was skipped, so a long-running PR never loses review comments silently.
- **Forgejo is called Forgejo** (#5, #11), not just on Codeberg. Notes and errors name a self-hosted Forgejo (and suggest `FORGEJO_TOKEN`) after `--forge forgejo`, for a host name with a `forgejo` part, or, only when there is an error to report, after one anonymous `/api/v1/version` request per host (2 s limit, cached for a day; if it fails the message says Gitea). Successful lookups, timeouts and connection errors never make that request. JSON `forge` stays `"gitea"` for both (same API).


## 0.2.0 – 2026-10-12
- **Line ranges.** `linelore file.py:10-30` blames the range, deduplicates commits (same sha once even when it owns many lines), and prints lore per unique commit in first-appearance order. `--json` adds `range` and a `commits[]` array; single-line `FILE:LINE` output is unchanged.
- **Follow moves and renames.** Blame runs with `-C -M` so lore follows code across renames and copies within a commit.
- **API response cache.** GitHub lookups are cached in memory for the process and on disk under `~/.cache/linelore` (or `$XDG_CACHE_HOME/linelore`), keyed by API host + request. Set `LINELORE_CACHE` to a directory to override, or to `off` / `0` / `none` to disable disk caching.
- **Promote Fixes/Closes/Resolves.** When GraphQL `closingIssuesReferences` is empty (common on older PRs), mentions like `Closes #6715` in the PR title or body are promoted to the fixes list.

## 0.1.1 – 2026-10-10
- Review comments that are not within a few lines of the blamed line are now labelled "elsewhere in this file" (or "outdated diff") instead of looking like they are about that line; JSON entries carry `near: true/false`.
- `--offline` now says "offline: showing local commit only" instead of the misleading "no GitHub remote".
- `--rev` no longer crashes when the file's directory does not exist in the working tree any more (e.g. `requests/adapters.py:250 --rev v2.31.0` after a move to `src/`).

## 0.1.0 – 2026-10-10
- First release: FILE:LINE → commit → PR → closing issues → mentions → nearby review comments. `--json`, `--offline`, `--rev`, `--repo`, `--api`, `.git-blame-ignore-revs`.
