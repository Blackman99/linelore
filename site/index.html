A

One command

pipx install git+https://github.com/Blackman99/linelore

linelore src/requests/utils.py:795

linelore src/requests/utils.py:795 --open

Python 3.9+ and git, no dependencies. Works on GitHub, GitLab and Gitea/Forgejo (Codeberg too), hosted or self-hosted, and reads which one from your remote. Works anonymously on public repos; tokens are optional (GH_TOKEN, GITLAB_TOKEN, GITEA_TOKEN). Pass file:10-30 for a range (commits deduped), --open to open the PR or MR in your browser, --json for editors and scripts, --offline for local only, --rev to blame at a tag. --summarize adds a paragraph from a model command you configured, printed under a label saying so, after the facts and never mixed into them.

B

Four hops

  1. 01

    Line → commit

    git blame --porcelain -w -C -M -L … (single line or a range; commits deduped). Skips .git-blame-ignore-revs. Local, no network.

  2. 02

    Commit → pull request

    Asks the forge that hosts the repo which PR (or GitLab MR) merged it, including squash and rebase merges.

    GitHub/repos/{o}/{r}/commits/{sha}/pullsGitLab/projects/:id/repository/commits/:sha/merge_requestsGitea, Forgejo/repos/{o}/{r}/commits/{sha}/pull, retried with the merge commit found locally

  3. 03

    PR → issues

    GitHub GraphQL closingIssuesReferences, GitLab closes_issues, or on Gitea the Fixes/Closes/Resolves #N references, each looked up for its title and state. If the forge has nothing, those references in the title or body are promoted. Any other #123 stays a mention.

  4. 04

    PR → review

    Review comments (GitLab diff notes, with their replies), matched to the line's position in that commit. Comments from elsewhere in the file are labelled as such.

C

In your editor

One key on the line you are reading. Neovim and Emacs read --json and lay it out themselves; VS Code and Helix show the text as it comes. Copy a file from editors/, nothing to install from a marketplace.
